## 已知限制与技术债

来自 README 的 [Limitations](README.md#limitations)，这里只列要点：

1. **没有实时控制**：核心没有 RA/SOAP，封禁/禁言/停用下一个登录才生效；解卡、改名要求角色**离线**。
2. **公会会长挡删号**：先在游戏里处理公会。
3. **不发邮件**：注册可以要求邮箱，但验证信与改密链接不发（`account.email_verif` 只显示不管理）。
4. **商城不动余额与流水**：`shop_coins`/`shop_logs` 不碰；删角色不退款。
5. **不清理日志表**：删号只删账号与角色。

`/db` 这边：

- 只有**四类**内容（物品、法术、任务、生物）——没有物件（gameobject）、区域、阵营等页面。
- 掉落表的 `groupid` 与 `condition_id` **已解释**（见上表最后一行）：组头给出「每组至多 1 件」与
  组内总概率，条件译成句子。两个已知边界：① 组内总概率只在该组各行来自**同一个**引用表时打印
  （跨引用表的同名组，那个和内核根本不会算）；② 条件的操作数名字里，`game_event` 只有英文描述
  （库里没有中文列，客户端这个版本也没有 Holidays.dbc），所以节日名会显示成 `Hallow's End` 这样的原文。
- 施法时间、持续时间、法术范围、法术效果索引**仍是原始数字**（客户端清单里没有那几个 DBC，
  猜出来的标签比原始索引更糟）。
- 不在任何区域框里的世界坐标**不画**（宁可没有地图，也不凭空造一个位置）。
- 图标还差 0.4%（约 20 个条目没有对应图标）。
- 性能：`/db` 有几条全表扫描的查询，README 的「关于性能」一节记了它们的量级与触发条件。
