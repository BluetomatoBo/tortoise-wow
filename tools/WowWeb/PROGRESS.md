## 已知限制与技术债

来自 README 的 [Limitations](README.md#limitations)，这里只列要点：

1. **没有实时控制**：核心没有 RA/SOAP，封禁/禁言/停用下一个登录才生效；解卡、改名要求角色**离线**。
2. **公会会长挡删号**：先在游戏里处理公会。
3. **不发邮件**：注册可以要求邮箱，但验证信与改密链接不发（`account.email_verif` 只显示不管理）。
4. **商城不动余额与流水**：`shop_coins`/`shop_logs` 不碰；删角色不退款。
5. **不清理日志表**：删号只删账号与角色。

`/db` 这边：

- 内容类目：物品、法术、任务、生物、**物件**；还没有区域页、阵营页与物品套装独立页。
- 物件页不解释 `data0`–`data23` 的含义：内核 `GameObject.h` 每种类型各有自己的结构体字段名，
  页面只列非零项与列下标（按类型命名是下一步，不是不做）。
- 掉落表的 `groupid` 与 `condition_id` **已解释**（见上表最后一行）：组头给出「每组至多 1 件」与
  组内总概率，条件译成句子。两个已知边界：① 组内总概率只在该组各行来自**同一个**引用表时打印
  （跨引用表的同名组，那个和内核根本不会算）；② 条件的操作数名字里，`game_event` 只有英文描述
  （库里没有中文列，客户端这个版本也没有 Holidays.dbc），所以节日名会显示成 `Hallow's End` 这样的原文。
- 施法时间、持续时间、法术范围、法术效果索引**仍是原始数字**（客户端清单里没有那几个 DBC，
  猜出来的标签比原始索引更糟）。
- 不在任何区域框里的世界坐标**不画**（宁可没有地图，也不凭空造一个位置）。
- 图标还差 0.4%（约 20 个条目没有对应图标）。
- 性能：`/db` 有几条全表扫描的查询，README 的「关于性能」一节记了它们的量级与触发条件。

### 第十五轮：点画到地图图片外面的 bug（`zoneGridBox` 少了一个包含检查）

用户接着报「`/db/npcs/61770` 有几个点飞出图片外，`/db/npcs/61701` 也是」。

* **根因**：`ZoneAt` 的四条分支里，**网格分支没检查「返回的区域框是否真的包含这个点」**
  （另外三条都有）。网格是 MCNK 格粒度、内容来自地形 areaid，在区域边缘会给出一个**框到不了**
  的区域：萨拉斯高地东北那几格，原版瓦片里还写着提瑞斯法/东瘟疫。点于是被按「萨拉斯高地」
  或「东瘟疫」的框算百分比 → 出界（实测 py = -44%~-51%、px = 112%~114%），画到图外的空白里。
* **修法**：`zoneGridBox` 加 `box.contains(x, y)`；不含就交回框规则 —— 框规则要么找到真正包含
  它的框（大陆兜底框 area 0 也行），要么按设计「不在任何区域框里的坐标不画」。
* **影响面**（复刻判定链跑了全库 154,935 个刷新点）：98.4% 不变；**1,446 个点从「画在图外」
  变成画在正确区域**（durotar→barrens、wetlands→azeroth 大陆图、barrens→orgrimmar 等）；
  19 个变成不画；**0 个原本正常的点被改动** —— 纯改进。
* **页面复核**：`/db/npcs/61770` 的 48 个点 = 萨拉斯高地 40 + 艾泽拉斯大陆 8，出界 **0**；
  `/db/npcs/61701` 全部 33 个点在萨拉斯高地，出界 **0**。
* 新增测试 `TestZoneAtNeverHandsBackABoxThatMissesThePoint`：钉住这条不变式 ——
  `ZoneAt` 返回的框必须包含该点（用那 5 个真实出界坐标 + 3 个正常坐标）。

### 第十六轮：贴边的点「半个圆露在图片外」（点的半径没算进去）

用户接着报 `/db/npcs/61770` 的点「不符合事实」。查下来是两个叠加的现象：

1. 上一轮的出界已经修掉（页面复核出界 0），但
2. 剩下 8 个点仍然是 **top 0.3%~1.6%** —— 它们站在萨拉斯高地框的**东边缘**（框 x 上限 4952、
   点在 x 4941~4946）。`.map-dot` 是 10px 圆点加 2px 描边、以坐标为中心（`margin: -5px`），
   图片 CSS 宽 480px → 半径 7px ≈ 图的 2.2%：top=0.3% 时**大半个圆在图片外面**，
   看起来就是「点飞出去了」。

* **修法**：`zoneBox.marker` 把百分比夹在 `dotMargin = 2.0` ~ `98.0` 之间（`clampPercent`）。
  代价是极边缘的点最多偏 2%（≈6 像素），收益是每个点都完整落在自己的地图上。
  任务目标点走同一个 `marker`，一起受益。
* 新增 `TestDotsStayOnTheArtwork`：东边缘那个真实坐标必须落在 2%~98% 内、中心附近的点不许被移动、
  框的四个角都夹住。
* 页面复核：`/db/npcs/61770` 40 点（萨拉斯高地）+ 8 点（艾泽拉斯大陆），出界 0，最靠边的 top = 2.0%。
* **数据侧的事实**（回答用户「不符合事实」）：那 10 个哨兵（x 4880~5150, y -3300~-3100）
  的 z 只有 3~5（海平面高度，萨拉斯高地其他哨兵 z≈58、陆地生物 z≈52），而且那片**只有它们**——
  附近没有任何物件、没有任何其他生物。也就是说这批刷怪点孤立地摆在萨拉斯高地以东的空白地形上，
  是**服务端刷怪数据**的样子，web 侧只能忠实显示；要动就得动刷新点本身。

### 查证（2026-10-10 深夜）：那 16 个哨兵是谁放的
